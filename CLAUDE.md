# CLAUDE.md — ksvb_app

## Tổng quan
- **Hệ sinh thái** (người dùng đang xây): HRM (`_Projects/hrm_app`) quản lý đơn vị/phòng ban và nhân viên và là nguồn gốc dữ liệu nhân sự; KSVB (dự án này) trình ký văn bản. Các hệ thống dùng chung một Postgres (mỗi hệ thống DB/schema riêng) và một Keycloak (realm `dev`) cho SSO, xác thực và phân quyền (client role riêng từng hệ thống). Mọi quyết định thiết kế KSVB phải khớp mô hình này: không tự quản lý đơn vị/nhân viên, không tự làm đăng nhập/mật khẩu.
- Hệ thống ký số văn bản (KSVB): **`ksvb-fe/`** (React) + **`ksvb-be/`** (Java Spring Boot). Tài liệu: `README.md` (chạy, API), `docs/requirements.md` (chức năng theo code), `docs/business-rules.md` (luồng ký, trạng thái, số hiệu), `docs/database.md` (ERD, Flyway), `docs/PHAN_QUYEN.md`; mọi tài liệu viết theo code hiện tại, không dựa bản phân tích/.NET cũ. Đổi nghiệp vụ thì sửa các file này cùng code. Giao diện: `docs/design/index.html` (preview bấm thử, xem dòng dưới).
- `docs/design/index.html`: bản preview bấm thử toàn bộ ksvb-fe, **build từ code thật** (`cd ksvb-fe && npm run build:design`, entry `ksvb-fe/src/design/`, backend giả trong bộ nhớ `src/design/demoBackend.ts`, một file HTML mở trực tiếp được). Nút tròn góc dưới phải đổi quyền (`role.user|leader|admin`, chưa có quyền); mở thẳng một màn bằng `#/đường-dẫn` (vd. `index.html#/documents/101/sign`). KHÔNG sửa tay file này: sửa giao diện hoặc dữ liệu mẫu trong code rồi build lại.
- `docker-compose.yml` (gốc): chỉ `ksvb-be` (host **8082**) + `ksvb-fe` (nginx không chạy root, trong container nghe 8080, host 3001, proxy `/api/` → `ksvb-be:8082`). KHÔNG có Postgres/Keycloak riêng: dùng bản đang chạy trên máy dev qua network ngoài `local-network` (giống HRM). Biến bắt buộc trong `.env` ở gốc: `KSVB_DB_URL` (jdbc:postgresql://<tên container postgres>:5432/ksvb), `KSVB_DB_PASSWORD`, `KSVB_OIDC_ISSUER_URI` (vd. http://localhost:8080/realms/dev), `KSVB_OIDC_JWK_SET_URI` (địa chỉ nội bộ Keycloak, vd. http://keycloak:8080/realms/dev/protocol/openid-connect/certs); tuỳ chọn `KSVB_DB_USER` (mặc định ksvb_app), `KSVB_CORS_ORIGINS`. KSVB dùng cổng riêng để chạy cùng lúc với HRM: backend **8082**, frontend dev **5174** (`strictPort`, bận thì báo lỗi chứ không nhảy cổng), frontend docker **3001**. ## Tích hợp Keycloak + HRM (backend + frontend ĐÃ làm, kiểm bằng test; CHƯA chạy thử trên Keycloak/Postgres thật)
- Cùng realm `dev` của HRM. Client `ksvb-web` (public, Authorization Code + PKCE, như `hrm-web`) và `ksvb-api` (chứa client role = quyền, như `hrm-api`) tạo bằng `docs/keycloak/setup-ksvb.sh` (chạy trong container Keycloak, chưa chạy thử; bot không chạy được). FE dùng `keycloak-js` (`ksvb-fe/src/auth.ts`, giống `hrm_app/frontend/src/auth.ts`).
- Token `iss` là địa chỉ trình duyệt thấy (vd. localhost:8080); container không gọi được `localhost` → trong Docker đặt `SPRING_SECURITY_OAUTH2_RESOURCESERVER_JWT_JWK_SET_URI` (compose lấy từ `KSVB_OIDC_JWK_SET_URI`) trỏ tên container Keycloak. KHÔNG khai báo `jwk-set-uri` rỗng trong yml (Spring tạo bộ giải mã sai).
- HRM là nguồn gốc người dùng/đơn vị/chức danh (Java 25 + Spring Boot 4.1, Postgres `hrm_db`, `/api/employees`, `/api/org-units`, `/api/positions`; sự kiện ra `hrm_outbox`, chưa có worker). KSVB không đọc thẳng `hrm_db`. Đã làm: `UserProvisioningService` tạo `app_user` ở lần đăng nhập đầu từ claim (`email`, `name`, `employee_code`, `unit_name`|`unit_code`, `position_name`|`position_code`) và cập nhật lại các lần sau. Chưa làm: lấy tên đơn vị/cây đơn vị từ API HRM (hiện hiện mã đơn vị nếu token không có tên).
- Đã đọc từ code HRM (chưa kiểm chứng trên Keycloak thật): tên host trong `local-network` là `postgres` (5432) và `keycloak` (8080); HRM chỉ chấp nhận token có `aud=hrm-api`, quyền = client role `hrm-api` (`employee.view`, `orgunit.view`, `position.view`...); `/api/me` của HRM đọc các claim `employee_code`, `unit_code`, `position_code` từ token (mapper phía Keycloak) → KSVB có thể lấy đơn vị/chức danh từ token nếu client `ksvb-web` có cùng mapper. HRM không có API riêng cho dịch vụ khác: gọi bằng JWT, service khác cần tài khoản dịch vụ (client_credentials) có các role `*.view` và audience `hrm-api`. Worker đồng bộ HRM→Keycloak (outbox) chưa có.
- Bí mật không ghi trong code: `application.yml` chỉ có `${KSVB_DB_PASSWORD}` (không mặc định). Chạy trên máy: `ksvb-be/.env` (backend tự đọc qua `spring.config.import`, mẫu `ksvb-be/.env.example`); Docker: `.env` cạnh `docker-compose.yml` (mẫu `.env.example`); frontend: `ksvb-fe/.env.local` (mẫu `ksvb-fe/.env.example`). Mọi `.env` đã gitignore.
- Bot không có quyền Docker và không dùng được `$KC_*` trong lệnh → không tự tạo client Keycloak được; cần người dùng chạy script/làm tay.
- Quyền KSVB (client role `ksvb-api`) và role tổng hợp `role.user|leader|admin`: xem `docs/PHAN_QUYEN.md` (viết theo code). Backend kiểm bằng `@PreAuthorize("hasAuthority('...')")`, danh sách ở `shared/security/Permissions.java`; thêm quyền mới phải thêm vào `ALL`, vào `docs/keycloak/setup-ksvb.sh` và tạo trong Keycloak.

- E2E: `ksvb-fe/e2e/` (Playwright, `npm run e2e`): tự chạy BE profile `h2` + FE dev không Keycloak; đổi người thao tác bằng cách sửa header `X-User-Id` (page.route). Cần JDK 25 (`JAVA_HOME`, trên Windows dạng `C:...`) và `npx playwright install chromium`. Đã kiểm: 2 kịch bản qua. CI có job `e2e`.

# KSVB – trình ký / ký số văn bản

## Tổng quan
- KSVB: soạn, trình ký và theo dõi văn bản PDF qua luồng ký nhiều người (tuần tự / song song). Người dùng, đơn vị, chức danh lấy từ HRM qua claim token; KSVB không tự quản lý đơn vị/nhân viên, không tự làm đăng nhập/mật khẩu, không đọc `hrm_db`.
- Chuẩn kiến trúc/công nghệ chung cho mọi app: `../../docs/kien-truc-chuan.md` (ĐÃ CHỐT; HRM và KSVB phải giống hệt, chỉ khác tên/gói/cổng/nghiệp vụ). Kiểm: `bash ../../docs/kiem-tra-chuan.sh`. Phần riêng của KSVB: `docs/kien-truc.md`.
- Tài liệu: `README.md` (chạy, cấu hình, API), `docs/` (`kien-truc.md`, `requirements.md`, `business-rules.md`, `database.md`, `phan-quyen.md`, `adr/`, `design/index.html`, `keycloak/setup-ksvb.sh`). Mọi tài liệu viết theo code hiện tại; đổi code thì sửa tài liệu cùng commit.

## Cấu trúc
- `backend/` (gói gốc `ksvb`): tính năng `signrequest` (văn bản, người ký, tệp, số hiệu, hết hạn), `template`, `user`, `report` (dashboard, báo cáo), `admin`; mỗi cái `api/` (controller mỏng), `application/` (service + DTO record), `domain/` (entity + luật nghiệp vụ, không Spring), `infra/` (repository, Specification, gửi thông báo); `config/` (`KsvbProperties`, `OpenApiConfig`); `shared/security` có `DevUserFilter` + `DevUserResolver` (cài đặt `user/infra/AppUserDevResolver`), `signrequest/infra` có `DocNumberGenerator` và `DemoDataLoader`.
- `backend/.../shared/`: `error` (`ApiErrorCode`, `GlobalExceptionHandler`, `ProblemResponses`, `BusinessException`, `ConflictException`, `NotFoundException`), `paging` (`PageResponse`), `persistence` (`Versions`), `security` (`Permissions`, `SecurityConfig`, `CurrentUser` (chỉ tên đăng nhập; bean người dùng đang thao tác là `user/application/CurrentAppUser`), `DevUserFilter`, `DevUserResolver`), `audit` (`Auditable`, `AuditLog`, `AuditService.log(action, target, detail)` ghi người thao tác từ SecurityContext, `BlockedActionAuditor`), `outbox`. Chiều phụ thuộc do `ArchitectureTest` kiểm.
- Test nằm cùng gói với lớp được test (không có gói `it/`). Ở gốc `ksvb`: `ArchitectureTest`, `PostgresIntegrationTest` (lớp nền Testcontainers), `OpenApiExportTest`.
- `frontend/src/`: `app/` (`main.tsx`, `App.tsx` = dựng route + kiểm quyền (thiếu quyền → `pages/ForbiddenPage`), `routes.tsx` = `ROUTES` tải lười (`perm` là một quyền hoặc mảng quyền), `nav.tsx` = menu/khung (`NAV`, `useNavBadges`...), `AppProviders.tsx`, `layout/` = `AppLayout`, `SideMenu`, `Topbar`, `useNav`, `pages/` = `ForbiddenPage`, `NotFoundPage`); `features/<f>/` (`pages/`, `components/`, `lib/`, `hooks.ts`, `api.ts`) với `dashboard`, `documents` (có `ItemList`, `PersonPicker`, `StatusTags`, `lib/constants`), `compose`, `templates`, `reports`, `admin`, `me`; `shared/` (`api` = `http.ts`, `queryClient.ts`, `types.ts`, `schema.d.ts` sinh tự động; `auth` = `keycloak.ts`, `session.tsx`, `permissions.ts`; `theme/ThemeProvider.tsx`; `ui` = PageHeader, PageState, StatusTag, PersonAvatar, ThemeSwitch; `lib/format.ts`); `design/` (backend giả + entry preview); `test/`.
- `frontend/`: `nginx/default.conf`, `openapi/openapi.json`, `design/index.html` (entry preview), `e2e/`, `knip.json`.
- `docker-compose.yml`: `ksvb-backend` + `ksvb-frontend`, network ngoài `local-network` (Postgres, Keycloak chạy riêng).

Role tổng hợp `role.user|leader|admin`: `docs/phan-quyen.md`.
- Frontend: `useSession()` (`me`, `can(quyền)`), menu theo quyền ở `app/nav.tsx`, quyền vào trang ở `app/routes.tsx` (`perm`; thiếu quyền hiện trang "Không có quyền truy cập"); backend luôn kiểm lại.
- Người dùng: `UserProvisioningService` tạo `app_user` ở lần đăng nhập đầu từ claim (`email`, `name`, `employee_code`, `unit_name`|`unit_code`, `position_name`|`position_code`), cập nhật các lần sau. Cột `app_user.role` chỉ dùng ở chế độ dev.

## Quy ước backend
- Lỗi: RFC 7807, `code` thuộc `VALIDATION_ERROR|UNAUTHORIZED|FORBIDDEN|NOT_FOUND|CONFLICT|BUSINESS_RULE|INTERNAL_ERROR`, mã nghiệp vụ ở `reason`, `errors[]` = `{field, message}`; chỉ ném `BusinessException` (422), `ConflictException` (409), `NotFoundException` (404), và `AccessDeniedException` của Spring Security cho 403 (service kiểm quyền trên văn bản, giữ thông điệp tiếng Việt); không ném `ResponseStatusException`. JSON trả cả `null`. Phân trang `PageResponse`.
- Luật nghiệp vụ ở entity domain (`signrequest/domain/SignRequest`: `SEQ`/`PAR` + bước ký `Participant.stepNo` (cùng bước ký cùng lúc, bước sau mở khi bước trước ký hết; tuần tự mà mọi người cùng bước thì đổi `PAR`), hoàn thành khi mọi người đã ký, từ chối/huỷ cần lý do, huỷ/thu hồi chỉ người tạo khi chưa ai ký, trình ký cần ≥1 người ký và ≥1 PDF), test thuần ở `*/domain/*Test`; service tải dữ liệu, kiểm quyền (403), kiểm `versionNo`, gọi luật, lưu, ghi audit + outbox.
- Mọi thao tác ghi gọi `AuditService.log(...)` và (với văn bản) `OutboxService.publish(...)` trong cùng transaction: `audit_log` **và** `ksvb_outbox`. Thao tác ghi bị chặn (403/409/422) được `BlockedActionAuditor` ghi `result=ERROR` (từ `GlobalExceptionHandler`, transaction riêng). Chưa có worker đẩy outbox (ADR 0001).
- Khoá lạc quan `version_no` (lớp `Auditable`): `PUT /api/sign-requests/{id}` bắt buộc `versionNo` của bản đang sửa, lệch → 409 `CONCURRENT_UPDATE`. Số hiệu `HD-2026-0001` sinh từ `doc_counter` có khoá ghi, không sinh ở code.
- Tệp: tên UUID do server sinh, kiểm đuôi + chữ ký `%PDF-`, tối đa 20 MB. Jackson 3 từ chối JSON thiếu trường `boolean` nguyên thuỷ trong record request → dùng `Boolean` cho cờ tuỳ chọn. Trường DTO có thể null gắn `@Nullable` (JSpecify) để OpenAPI đúng.
- Lớp mới phải đặt đúng tầng: `ArchitectureTest` chặn sai chiều phụ thuộc, controller trả entity, repository ngoài `infra`.
- Ảnh chữ ký: `user/application/SignatureService` + `SignatureImageProcessor` (tách nền Java thuần), API `/api/me/signature`; preview dùng `frontend/src/design/demoSignature.ts` (cùng thuật toán, canvas). Ô ký: annotation trong PDF (không lưu DB), `signrequest/infra/PdfSignatureSlots` (PDFBox: đọc/ghi ô, render trang), `SignSlotService`, luật khớp người ký `domain/SignSlot.requireMatch` khi trình ký; giao diện bước Vị trí ký `features/compose/components/SlotEditor`. Ký: `SignRequestService.sign` đóng ảnh chữ ký vào ô (`PdfSignatureSlots.stamp`, font LiberationSans có sẵn trong PDFBox) thành bản đã ký `attachment.signed_stored_name` (kèm dung lượng + SHA-256), bản gốc giữ nguyên. Ảnh chữ ký người ký cho người soạn xem trước: `GET /api/sign-requests/{id}/signer-signatures`. Giao diện: `compose/components/FilePreview` (xem tệp ở bước 1), `documents/components/SignedPdfView` (xem trang, xem trước mọi ô, chuyển bản gốc), `SignedFileInfo` (thông tin bản đã ký). `DemoDataLoader` ghi PDF mẫu có sẵn ô ký, chữ ký mẫu cho người 1, 2, 3, 6 (người 4 chưa có). Chưa làm: gửi email thật, ký số PKI thật, phân quyền dữ liệu theo đơn vị, lấy tên đơn vị từ API HRM.

## Quy ước frontend
- Gọi API qua `shared/api/http.ts` (`fetch`, gắn token, ném `ApiError{status, code, detail, reason, errors, body}`); mỗi tính năng có `api.ts` (`<f>Api`) và `hooks.ts` (TanStack Query). Kiểu API KHÔNG viết tay: `shared/api/types.ts` chỉ đặt tên cho schema sinh ra (`schema.d.ts`).

- Màu chỉ lấy qua `theme.useToken()` (màu chủ đạo `#1668dc` đặt trong `ThemeProvider`); thông điệp tiếng Việt. Trang giấy sơ đồ chữ ký (`documents/components/Paper.tsx`) luôn theme sáng.
- Menu trái thu gọn được (phím `[`, localStorage `ksvb.sidebar.collapsed`), dưới 1024px thành ngăn kéo. Không dùng `List` của Ant Design (deprecated) → `features/documents/components/ItemList`; `Alert` dùng `title`; ô `<input type=file>` ẩn dùng `style={{display:'none'}}`.
- Backend giả `src/design/demoBackend.ts` dùng chung cho preview, test giao diện (`src/test/fakeFetch.ts`) và E2E (`e2e/mockApi.ts`): thêm API mới mà giao diện gọi thì thêm phản hồi ở đó. Preview `docs/design/index.html` không sửa tay, build lại bằng `npm run build:design`.
